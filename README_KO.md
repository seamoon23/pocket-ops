# Pocket Ops · 폐쇄망 미니 공구함

**v0.8.0 / 2026-11-25**

명령어가 기억나지 않을 때, 한글이 깨졌을 때, 로그와 목록을 정리할 때 꺼내 쓰는 로컬 HTML 작업실입니다. **실행 파일은 `pocket-ops.html` 한 개**입니다. JavaScript, CSS, 명령어 데이터, 아이콘과 읽기 전용 참고 내용을 파일 안에 포함했습니다. 별도 실행 폴더는 필요하지 않으며 PC와 휴대폰에 같은 파일을 저장합니다.

## 가장 빠르게 시작하기

**명령어 포켓 → Windows / Linux / DB / Git → 확인·복사**에서 기준 파라미터와 설명을 구문 위에서 확인하세요. 기존 입력란이 있는 명령은 값을 바꾸고 최종 미리보기를 확인합니다. 고정 예시는 복사 후 텍스트 편집기에서 경로·옵션을 조정합니다. **메뉴 → 로그 돋보기 → 점검 예시 → 예시 적용**은 가상 로그와 필터를 함께 채웁니다.

**내 작업실 → 실무 가이드 11편 → 글 제목**에서 PowerShell, Ubuntu 22.04, RHEL 7, DB 점검과 예시 결과를 읽습니다. 명령 이름을 누르면 입력 위치·미리보기·복사가 열립니다. CSQL·JSON·로그 글은 **도구에서 예제로 열기**를 누르세요. JavaScript가 차단된 뷰어에서는 **읽기 전용 명령어 참고 → 실무 가이드 11편**에서 같은 글을 읽고 기본 명령 원문으로 이동할 수 있습니다.

1. `pocket-ops.html`을 작업 PC의 일정한 폴더에 저장합니다.
2. 기관의 HTML·JavaScript·망간 파일 반입 정책을 확인하고 허용된 절차로 옮깁니다.
3. 허용된 Chromium 기반 Chrome/Edge 브라우저에서 파일을 엽니다. HTML 편집기 대신 브라우저로 열어야 합니다.
4. 첫 화면 대시보드에서 **Windows PowerShell / Linux 셸 / DB · SQL 작업대** 중 작업 위치를 고르거나, 검색창(`Ctrl+K`)으로 도구·명령어를 찾습니다. 즐겨찾는 명령과 도구는 대시보드에 바로 표시됩니다.
5. 처음 쓰는 화면은 제목 오른쪽(휴대폰은 제목 아래) **사용 예시**를 누릅니다(PC 키보드 `?`). 순서·입력 예·결과 예·주의가 나오고, **이 예시로 해보기**를 누르면 그 화면에서 예시가 그대로 실행됩니다. 창 아래 `다른 화면의 사용 예시`에서 18개 화면의 예시를 모두 볼 수 있습니다.

GitHub → [최신 배포](https://github.com/seamoon23/pocket-ops/releases/latest) → Assets → **pocket-ops.html**을 선택하면 단일 파일을 받을 수 있습니다. ZIP에는 HTML과 안내문 세 개가 들어 있으며, 사용에 필요한 파일은 HTML 하나입니다.

**실행에 인터넷, 계정, API 키, Node.js, Python, WAS 설치가 필요하지 않습니다.** 압축본의 개발 소스나 테스트 파일도 실행에는 필요하지 않습니다. 단, 기관 브라우저가 로컬 HTML 또는 JavaScript 실행을 막으면 먼저 담당자에게 허용 여부를 확인하세요. 보안 정책을 우회하는 기능은 없습니다.

RHEL 7·JEUS 6 서버 위에 설치하는 제품이 아닙니다. 작업 PC의 브라우저에서 명령어를 확인하고 사용자가 터미널에 복사해 쓰는 도구입니다. IE / IE 호환 모드는 지원 대상이 아닙니다.

## 갤럭시에 미리 저장해서 보기

1. 인터넷이 되는 곳에서 위 배포 페이지 → Assets → `pocket-ops.html`을 내려받습니다.
2. **홈 화면 위로 밀기 → 앱스 → 내 파일 → 다운로드 → pocket-ops.html**을 엽니다. 내 파일이 보이지 않으면 앱스 검색에서 ‘내 파일’을 검색하세요. 다운로드 위치는 앱 설정에 따라 다를 수 있습니다. [삼성 다운로드 파일 안내](https://www.samsung.com/uk/support/mobile-devices/where-can-i-find-downloaded-files-on-my-samsung-galaxy-smartphone/)
3. 연결 앱 선택이 나오면 이미 설치된 허용된 브라우저 또는 HTML 뷰어를 선택합니다. 갤럭시/Android 버전과 연결 앱마다 로컬 HTML 실행 방식이 달라 특정 앱이 항상 목록에 나오거나 모든 기능이 작동한다고 보장하지 않습니다.
4. 첫 화면의 **Windows PowerShell / Linux 셸 / DB** 카드를 누르거나 **상단 메뉴 → 명령어 포켓**, 상단 검색 버튼을 사용합니다. 모든 명령 카드의 `입력:` 줄이 붙여넣을 곳입니다. 메뉴는 닫기 버튼·어두운 배경 터치로, 검색은 닫기 버튼으로 닫습니다. 복사가 제한되면 안내창에서 **텍스트 길게 누르기 → 모두 선택 → 복사**를 시도합니다.
5. 방문 전에 네트워크를 끄고 파일을 다시 열어 명령어 표시를 확인합니다. 현장에서 휴대폰 사용이 허용되는 경우 참고용으로 사용하세요.

**읽기 전용 모드:** JavaScript가 꺼져 있거나, 켜져 있어도 뷰어가 스크립트를 차단·변형해 앱이 시작되지 못하면 같은 파일 안의 ‘읽기 전용 명령어 참고’가 표시됩니다(차단된 경우 약 1.5초 뒤). Windows/Linux/DB 분류 링크, 기본 명령어 176개, 각 명령의 입력 위치·조건·주의·대체 항목을 읽을 수 있습니다. 검색·즐겨찾기·변환·자동 복사·값 검증·배포하기는 작동하지 않습니다. `{{PORT}}`, `{{PATH}}` 등은 입력 자리이므로 그대로 실행하거나 단순 치환해 붙여넣지 마세요. HTML을 원문 코드로만 보여 주거나 HTML 자체를 차단하는 앱에는 이 모드도 표시되지 않습니다.

화면은 320px부터 세로·가로 폭에 맞춰 배치됩니다. 16px 입력 글자, 14px 명령어, 주요 44px 터치 버튼을 사용하며 휴대폰에서는 카드가 한 열로 배치됩니다. 실제 갤럭시 단말의 파일 연결·저장·OS 클립보드는 개발 PC의 모바일 화면 모사와 별개로 확인해야 합니다.

## 환경별 찾기와 배포

- **대시보드:** 왼쪽 `내 작업실` → 검색창, 작업 위치 카드(Windows PowerShell / Linux 셸 / DB · SQL 작업대), 즐겨찾는 명령·도구. 15개 도구 전체는 `모든 도구` 펼치기에 있습니다.
- **명령어와 대안:** 왼쪽 `명령어 포켓` → 환경 탭 → 분류/검색 → `값 넣기 · 복사`. 카드의 `입력:`이 Linux 셸(`$`), Windows PowerShell(`PS>`), `csql>`, `MariaDB>`, `SQL>`, `psql =>` 중 어디인지 확인합니다. 도구가 없으면 창 아래 `사용할 수 없을 때`에서 각 대안의 입력 위치·조건을 비교해 하나를 고릅니다. 입력한 값은 대안으로 이어지고 `← 원래 명령으로`로 돌아갈 수 있습니다. 대안은 기능 범위가 다를 수 있으며 자동으로 연속 실행하지 않습니다.
- **즐겨찾기:** 도구 또는 명령어의 별표 → 왼쪽 `즐겨찾기`. 두 종류를 한곳에서 볼 수 있습니다.
- **사용 예시:** 모든 화면 제목 줄의 `사용 예시` → 이럴 때 · 순서 · 입력 예 · 결과 예 · 주의. `이 예시로 해보기`는 예시 값을 그 화면 입력칸에 넣고 같은 버튼을 누릅니다. 직접 입력한 내용이 있으면 바뀔 칸을 먼저 알려 주며, 창을 닫으면 아무것도 바뀌지 않습니다.
- **ZIP 배포:** 상단 `배포하기` → `pocket-ops-v0.8.0.zip` 저장. HTML 원본과 사용안내·변경 기록만 포함하며 작업 입력, 불러온 파일, 개인 명령어와 설정은 제외합니다. 기본 Windows ZIP 풀기와 호환되는 무압축 저장 방식입니다.
- **업데이트:** 연결 가능한 개발 PC → [GitHub 저장소](https://github.com/seamoon23/pocket-ops) → 최신 버전 ZIP → 승인된 망간전송 → 탐색기에서 `모두 압축 풀기` → `pocket-ops.html` 열기. `배포하기`는 현재 열어 둔 버전을 다시 포장하며 온라인 최신 버전 확인은 하지 않습니다.

Windows 예제는 Windows 11의 Windows PowerShell 5.1을 기준으로 합니다. Linux는 Ubuntu 22.04/RHEL 7의 기본 명령을 우선하고 `ss`, `ip`, `systemctl`, JDK·WAS·Docker 등 설치에 따른 차이는 항목에 표시합니다. DB 명령은 접속 명령만 Linux 셸에 입력하고, 그 뒤의 세션 명령과 SQL은 각 DB 클라이언트 프롬프트(`csql>`, `MariaDB>`, `SQL>`, `psql =>`)에 입력합니다.

업데이트 전 `내 포켓 관리 → 설정 백업`을 저장하고, 새 파일은 별도 폴더에서 샘플로 시험한 뒤 `설정 가져오기`로 옮기세요. 저장소는 파일 경로에 따라 분리될 수 있습니다. 내려받은 ZIP/HTML의 파일 지문은 저장소의 `SHA256SUMS.txt`와 비교할 수 있습니다. Windows 시작 메뉴 → Windows PowerShell → 파일이 있는 폴더에서 `Get-FileHash -Algorithm SHA256 -LiteralPath .\pocket-ops-v0.8.0.zip`을 실행합니다. 체크섬은 손상 비교용이며 디지털 서명이나 보안 인증은 아닙니다.

## SSH에서 DB 작업하기 (CUBRID · MariaDB · Oracle · PostgreSQL)

**경로:** 첫 화면 → DB · SQL 작업대 카드 → DB 선택 (또는 메뉴 → 서버 운영 → **SQL 작업대**). 화면 위에서 고른 DB에 맞춰 `작업 순서`와 붙여넣을 프롬프트가 바뀝니다. 명령어 포켓 → DB 탭 → DB 버튼으로 같은 명령을 목록으로 볼 수도 있습니다.

1. **접속 · Linux 셸:** 조회 전용 또는 변경 작업용 접속을 눌러 계정·DB를 입력하고 복사해 SSH 터미널의 셸(`$`)에 붙여넣습니다. 비밀번호는 명령행에 넣지 않고 클라이언트의 비밀번호 프롬프트에 입력합니다. CUBRID `csql -C -r`(읽기 전용)·`--no-auto-commit`, MariaDB `mysql -p --safe-updates`, Oracle `sqlplus -L 사용자@별칭`, PostgreSQL 읽기 전용(`default_transaction_read_only`)·수동 커밋(`AUTOCOMMIT=off`) 접속을 제공합니다.
2. **대상 · 자동 커밋 확인 · 클라이언트 프롬프트:** `;database`/`;autocommit`(CUBRID), `SELECT DATABASE() … @@autocommit`(MariaDB), `SHOW USER`/`SHOW AUTOCOMMIT`(Oracle), `\conninfo`/`\echo :AUTOCOMMIT`(PostgreSQL)로 대상과 자동 커밋을 확인합니다. 테이블 구조 확인으로 키 컬럼을 확인합니다.
3. **트랜잭션 시작:** MariaDB는 트랜잭션 지원 테이블과 새 변경 세션을 확인한 뒤 `START TRANSACTION;`, PostgreSQL 자동 커밋 세션은 `BEGIN;`을 먼저 실행합니다. Oracle은 값에 `&`가 있으면 `SET DEFINE OFF`를 먼저 실행합니다. CUBRID 변경 작업용 접속은 별도 명령이 없습니다.
4. **쿼리 작성:** SELECT/INSERT/UPDATE/DELETE 프리셋을 누르면 아래 SQL 원문에 예시가 들어가고 예시 테이블명이 선택됩니다. 테이블명·값·WHERE 조건을 바꾸고 **복사** 또는 결과 저장을 누릅니다. INSERT·UPDATE·DELETE와 결과를 기록하거나 행을 잠그는 SELECT(INTO, FOR UPDATE 등)는 확인 창에서 붙여넣을 곳, DB별 순서, 점검 결과와 **그대로 복사될 최종 SQL**을 보여 줍니다. WHERE가 없는 UPDATE·DELETE는 위험 확인 체크 전까지 복사·저장 버튼이 잠깁니다. 예시 테이블 `pocket_ops_sample`이 남아 있으면 경고합니다.
5. **확정 · 취소 · 종료:** 영향 행 수가 예상과 같을 때만 확정합니다. Oracle SQL*Plus의 `EXIT`는 기본적으로 커밋하므로 `EXIT ROLLBACK`을 제공합니다. MariaDB·PostgreSQL은 연결을 끊으면 미확정 변경이 롤백됩니다.

명령어 포켓 → DB → 원하는 DB → SQL 작업대에서 순서대로 보기를 누르면 선택한 DB가 이어집니다. Oracle 치환 문자와 psql 변수가 있는 SELECT, 하위 쿼리에서 행을 잠그는 SELECT도 복사·저장 전에 확인합니다. MariaDB에서 트랜잭션을 다시 시작하면 기존 변경이 확정됩니다.

DB별 점검: Oracle은 SQL*Plus가 빈 줄에서 문장을 끊고 `/`·`.`만 있는 줄을 실행·종료로 읽으므로 이런 SQL을 정렬하지 않습니다. PostgreSQL은 `:이름`이 psql 변수로 바뀐다고 경고합니다. MariaDB·MySQL이 실행하는 `/*! */` 주석과 공백 없는 `--`는 거부합니다. `//` 주석은 CUBRID에서만 허용합니다. 예제의 `pocket_ops_sample`, `item_id`, `item_name`은 가상의 이름입니다. 다른 프리셋을 열 때 기존 편집 내용이 있으면 교체 여부를 묻고, 취소하면 원문과 선택한 DB를 그대로 둡니다. DB를 바꾸면 이전 DB 기준의 정렬 결과를 지웁니다.

| 확인 결과 | 다음 작업 |
|---|---|
| DB·호스트가 예상과 다르거나 자동 커밋 상태를 확인할 수 없음 | 변경을 중지하고 연결 대상과 세션 설정 확인 |
| INSERT 대상 키가 이미 존재함, 또는 UPDATE/DELETE 사전 조회의 행 수·기존 값이 예상과 다름 | 조건과 스키마를 재확인한 뒤 다시 조회 |
| 수동 커밋 세션에서 변경 후 영향 행 수가 예상과 다름 | 확정을 중지하고 해당 트랜잭션의 미확정 작업을 확인한 뒤 취소 판단 |
| 영향 행 수와 변경 후 조회 결과가 예상과 일치함 | 승인된 작업 범위대로 현재 트랜잭션을 확정할지 판단하고 종료 |

`;commit`·`COMMIT;`과 `;rollback`·`ROLLBACK;`은 현재 트랜잭션의 미확정 작업 전체에 적용됩니다. 식약처 실제 서버 버전·스키마·권한에는 현장 확인이 필요합니다.

## 세 가지 사용 예

### 포트를 알고 싶은데 root 계정은 없을 때

첫 화면 → **Linux 셸 · SSH** 카드 → 검색창에 `포트` → ‘특정 포트 리스닝 확인’의 **값 넣기·복사**에서 `8111`을 입력하고 최종 명령어와 `입력: Linux 셸 · $`를 확인합니다. `ss`가 없으면 창 아래 대안(netstat, /proc)의 조건을 비교해 고릅니다.

```bash
ss -lnt "( sport = :8111 )"
```

조회 가능한 범위만 보여 줍니다. 리스닝, 방화벽 통과, 외부 접속 성공은 서로 같은 판정이 아닙니다. 검색 결과가 없다는 이유만으로 미설치를 단정하지 마세요. 이 앱은 위 명령을 실행하지 않습니다.

### 오래된 CSV/TXT 한글을 다시 읽고 싶을 때

‘한글·인코딩 진료소’에서 **원본 파일**을 선택합니다. UTF-8로 깨져 보이면 EUC-KR / Windows-949 계열을 선택하고 실제 내용을 대조합니다. 정상임을 확인한 뒤 UTF-8로 새 파일을 저장합니다. 원본을 덮어쓰지 않습니다. 일부 프로그램에 필요한 경우 UTF-8 BOM 옵션을 켭니다.

첨부한 `samples/korean-cp949.txt`에는 `갂`, `똠` 등 확장 한글이 포함되어 있습니다. 내용 비교용 UTF-8·UTF-16 파일도 제공합니다.

원본 바이트가 남아 있는 파일 재읽기와, 이미 깨진 문자열에서 바이트를 추측해 되살리는 것은 다릅니다. 복구 후보 기능은 Latin-1 또는 Windows-1252로 잘못 읽힌 경우만 가정합니다. 모든 한글 깨짐을 복원하지 않습니다. 이미 대체된 `�` 또는 `?`는 원래 정보가 없으면 확정 복원할 수 없습니다. UTF-8 내보내기만 지원하고 EUC-KR/CP949로 다시 저장하지는 않습니다.

### DB 조회용 ID 목록을 정리하고 싶을 때

‘텍스트 다듬기’에서 중복과 빈 줄을 정리한 뒤 ‘SQL IN 도우미’에 붙여넣습니다. 값의 종류를 문자열/숫자로 명시하고 컬럼명을 확인합니다. `00123`처럼 앞의 0이 의미 있다면 문자열을 선택합니다. 1,001개 이상은 기본 설정에서 OR 묶음으로 나눕니다.

숫자 모드는 숫자를 JavaScript Number로 변환하지 않아 긴 ID의 자릿수를 유지합니다. 문자열 모드는 DB별 이스케이프 해석 차이 때문에 역슬래시와 제어문자를 거절합니다. 이런 값은 실제 DB 클라이언트의 매개변수 바인딩을 사용하세요. 결과는 점검용 SQL 조건문이며 DB별 SQL 모드·바인딩·실행 계획 검토를 대신하지 않습니다.

## 찾기·개인화

`Ctrl+K` 또는 입력 칸 밖의 `/`로 통합 검색을 엽니다. 방향키와 Enter로 선택하고 Esc로 닫습니다. 상단의 달/해 버튼은 라이트·다크 전환입니다. 별표는 도구 또는 명령어 즐겨찾기입니다.

‘내 명령어 추가’는 명령어 원문을 저장합니다. 자동 치환이나 실행을 하지 않습니다. 비밀번호·토큰·개인정보를 넣지 마세요. 직접 저장한 명령어와 가져온 명령어는 모두 미검증 명령으로 취급하여 복사 전 확인을 요구합니다.

기본 명령어는 조회 중심, 부하 주의, 실제 변경으로 구분했습니다. 프로세스 종료, 권한 변경과 부하가 있는 작업은 내용을 확인해야 복사 버튼이 활성화됩니다. PID·포트는 형식/범위를 검사하고 Bash/PowerShell 매개변수는 인용합니다. 경로가 `-`로 시작하면 `./`를 붙이도록 안내합니다. 이러한 보조 장치가 실제 작업의 안전성을 보증하지는 않습니다.

## 저장되는 것 / 저장되지 않는 것

앱이 자동으로 영구 저장하는 것은 테마, 즐겨찾기, 사용자가 명시적으로 추가한 명령어뿐입니다. 로그, 변환 입력·결과, 선택한 파일 내용은 자동으로 localStorage에 저장하지 않습니다. 도구를 전환해도 입력은 현재 탭의 메모리에 남습니다.

‘내 포켓 관리 → 설정 백업’으로 JSON을 저장하면 개인 설정을 다른 PC로 옮길 수 있습니다. 백업에는 내 명령어 원문이 평문으로 포함됩니다. 입력 로그나 변환 결과는 포함되지 않습니다. 가져오기는 기존 설정을 교체하며 확인 창을 표시합니다.

설정 가져오기는 최대 16 MiB, 내 명령어 200개·각 8,000자까지 허용합니다. 보안 검토를 거치지 않은 사용자 명령으로 취급하며, 백업 파일의 위험도 표시는 신뢰하지 않습니다.

`file://`에서의 localStorage 동작은 브라우저·경로·관리 정책에 따라 달라질 수 있습니다. 파일 이름/위치나 PC를 바꾸기 전에 백업하세요. 저장소가 차단되면 경고를 표시하고 현재 탭에서만 설정을 유지합니다.

상단 휴지통은 현재 열린 도구의 입력·결과·파일 참조를 초기화합니다. 즐겨찾기와 내 명령어는 유지합니다. OS 클립보드, 다운로드한 파일, 브라우저 세션 복원, OS 메모리의 보안 삭제까지 처리하지는 않습니다.

## 외부 통신과 보안 범위

실행 HTML에는 외부 라이브러리, CDN, 원격 폰트, 분석 코드, 광고, API 호출이 없습니다. 메타 CSP에서 `connect-src 'none'`, `default-src 'none'` 등을 적용했습니다. 정규식은 로컬 Blob Worker에서만 실행하고 시간 초과 시 종료합니다. 입력 문자열을 HTML이나 JavaScript로 실행하지 않습니다.

이는 이 페이지 자체의 설계 범위입니다. 브라우저 확장 프로그램, OS 보안 프로그램, 클립보드 동기화, 관리 솔루션의 동작까지 통제하는 제품은 아닙니다. 업무 자료와 생성된 파일을 반출할 때는 기관 규정을 따르세요.

## 복사·파일 저장·브라우저 제한

자동 복사는 Clipboard API → 구형 copy 대체 경로 → 수동 선택/복사 창 순서로 시도합니다. 브라우저나 관리 정책상 자동 복사가 막혀도 텍스트를 직접 선택해 복사할 수 있도록 구성했습니다. API 사용에는 보안 컨텍스트와 권한 제한이 있고 대체 API는 deprecated입니다. 모든 관리형 브라우저의 성공을 보장하지 않습니다.

Web Crypto가 없는 컨텍스트에서는 해시 계산이 불가하다는 안내를 표시합니다. 명령어 포켓의 `sha256sum` 또는 PowerShell `Get-FileHash` 예제를 대신 참고할 수 있습니다. Worker가 차단되면 정규식을 메인 화면에서 강제로 실행하지 않고 중단합니다.

내부 HTTP 서버에 HTML을 올리는 것도 구조상 가능하지만 이 버전에서는 서버 배포를 검증하지 않았습니다. 특히 일반 HTTP에서는 일부 보안 컨텍스트 API에 제약이 있을 수 있습니다. 운영 배포 전 기관 환경에서 확인하세요.
